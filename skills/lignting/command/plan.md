# lignting plan —— 需求规划（/lt-plan、/ltpl）

目标：把一条需求描述变成一份可直接开工的完整修改计划，中间只问该问的问题，
不反复确认已经明确的方向。

## 第 0 步：codegraph 前置检查

调用 `codegraph_status`。未初始化（项目无 `.codegraph/`）→ 立即停止，要求用户运行
`codegraph init -i` 后重试，不得绕过探索。

## 第 1 步：判定模式（精确 / 粗略）

把用户的需求描述按信息完整度分成两档：

| 特征 | 模式 |
|---|---|
| 行为、样式参照、跳转链接、端侧（云机/浏览器）、字段名等细节齐全，描述都是确定性表达 | **精确模式** |
| 信息不全，或含有"我想""大概""类似""考虑"等不确定/探索性表述 | **粗略模式** |

> 混合描述按较粗的一档处理（宁可多问一轮，不要替用户拍板方向）。

## 第 2 步：探索阶段（强制 lignting-explore）

探索一律通过 `subagent_explore` 工具进行（它只允许 codegraph 工具、快速模型；
若它告警 codegraph 未初始化，停止并按第 0 步处理）。涉及多个模块/多条链路时，
**一次并行开多个 `subagent_explore`**，按模块切分任务，各自输出符号/文件/调用链。

- **精确模式**：
  1. 用 `subagent_explore` 定位需求涉及的所有文件、入口、现有类似实现（用户给了参照样式就找参照实现）。
  2. 基于探索结果整理出大致修改方案。
  3. 把方案里**无法从代码确定、必须用户拍板**的点整理成问题清单。

- **粗略模式**（两轮提问）：
  1. **第一轮**：先用 `subagent_explore` 做一次轻量探索（确定需求大概落在哪些模块、
     有哪几个可行方向、初步遇到哪些不确定点），然后向用户提问确定大概方向。
  2. 拿到第一轮答复后，**带着结论再探索**：并行开 `subagent_explore` 深挖选定方向，确定大致修改方案。
  3. 和精确模式一样，把剩余不确定点整理成问题清单，进行第二轮提问（只问细节，不重复问方向）。

## 第 3 步：提问阶段

按 lignting skill 的"提问规范"执行：
- 优先 `ask_user_question`，每个问题带选项，推荐项放第一位；
- 每轮 ≤6 题：>6 拆两轮、>12 拆三轮，以此类推；
- 只问问题清单里的点；已在需求里明确的信息绝不重复问。

## 第 4 步：输出计划

所有问题确认后，直接向用户输出完整计划，包含：

1. **需求完整描述**：用户原话 + 确认后的细节，整合成无歧义的需求陈述
   （含端侧、参照、链接、验收要点）。
2. **完整修改计划**：
   - 按子系统/文件分组列出改动；
   - 每个改动点：文件、大致位置、改动内容、改动原因；
   - 边界情况与失败场景；
   - 明确不做的事（防止顺手改无关代码）；
   - 需要同步双端（云机/浏览器）或新增字段覆盖层级的，显式列出。

计划输出后等待用户确认；确认后才进入编码，编码遵循最小改动原则。
