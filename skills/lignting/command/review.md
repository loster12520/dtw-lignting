# lignting review —— 代码审查（/lt-review、/ltrv）

纯审查角色：**不修改任何代码**。支持 `low` / `middle` / `high` 三档（无 max）。

## 第 0 步：codegraph 前置检查

调用 `codegraph_status`。未初始化（项目无 `.codegraph/`）→ 立即停止，要求用户运行
`codegraph init -i` 后重试。

## 第 1 步：参数解析

```
/ltrv                              → level=middle, scope=自动检测
/ltrv low|middle|high              → 指定级别
/ltrv high 浏览器下发                → level=high, scope="浏览器下发"
/ltrv 浏览器下发页面                 → level=middle, scope="浏览器下发页面"
scope 含"放到/保存到/输出到"后跟路径  → 提取 savePath（默认保存见第 5 步）
均不匹配                            → scope 整体作为搜索描述
```

## 第 2 步：范围检测

1. 有 scope 描述 → 用 `codegraph_search` + grep 定位文件；
2. 无 scope → 读 `.lignting/.cr-state.json`（存在则对比当前 git diff：
   新修改文件与上次 `reviewedFiles` 无重叠 → 只扫新文件；有重叠 → 全额扫）；
3. 无状态文件 → `git diff --staged` + `git diff`（未提交代码）；无 diff →
   输出 "❌ 没有可审查的代码：当前对话未修改文件，且工作区无未提交更改。" 结束。

## 第 3 步：状态目录初始化（幂等，用户无感）

在创建 `.lignting/` 下任何文件**之前**，按顺序执行：

1. 检查 `<项目根>/.git/info/exclude` 是否存在，不存在则创建（git 本地排除文件，不影响仓库）；
2. 若其中没有 `.lignting/` 行，追加 `.lignting/`（屏蔽整个 lignting 文件夹）；
3. 创建 `.lignting/` 目录（报告目录 `.lignting/doc/review/` 按需创建）；
4. 用 `git check-ignore .lignting/` 验证已被忽略。

全程静默完成，不向用户解释，不要求用户改任何 git 配置。

## 第 4 步：按档位并行审查

> 所有子代理用 `subagent` 工具，`run_in_background: false`，同一轮内一次并行启动。
> 子代理的结构查询一律用 codegraph（遵守 lignting 公共约束）。
> 每个子代理的 prompt 从下方模板内联，替换 {fileList}（审查范围文件清单 + 简要变更说明）。

### low —— 档 1（1 个子代理）

```
你是代码审查员（档1）。只检查以下文件的正确性、一致性、完整性与安全性，不修改任何代码：
{fileList}
- 正确性：逻辑错误、边界条件、异步时序、空值/越界、错误处理缺失
- 一致性：与周边代码风格/模式一致、命名统一
- 完整性：改动自洽、有无遗漏配套修改（类型/表单/回填/日志映射等）
- 安全性：注入、敏感信息泄露、权限绕过、XSS/CSRF 等红线
每个问题给出：文件 + 行号/片段 + ❌/✅ 前后示例。没有问题的维度明确写"✅ 未发现明显问题"。
```

### middle —— 档 2（3 个子代理并行：可读性 / 安全性 / 性能）

通用模板（每个子代理替换 {方向} 为下表对应维度，并只审该维度）：

```
你是代码审查员（档2-{方向}）。基于以下未提交改动审查，不修改任何代码：
{fileList}
请用 git diff 获取变更内容，按 {方向} 维度逐条审查，每个问题给出文件+行号+❌/✅ 前后示例，
按 🔴Critical / 🟡Important / 🟢Suggestion 分级。没有问题的维度明确写"✅ 未发现明显问题"。
```

| 方向 | 审查要点 |
|---|---|
| 可读性 | 命名是否清晰一致；函数是否过长/职责单一；嵌套层级是否合理(≤3)；注释是否准确；魔数/魔法字符串是否应抽常量；是否与代码库既有模式一致 |
| 安全性 | 注入风险；敏感数据泄露(日志/存储/前端)；鉴权绕过；外部输入校验；XSS/CSRF |
| 性能 | 冗余计算；循环可优化点；重复请求；渲染循环内昂贵操作；内存泄漏(未清理 listener/timer/subscription)；异步竞态；N+1 查询；防抖/批处理 |

### high —— 档 3（8 个子代理并行）

档 2 的 3 路（可读性/安全性/性能）+ 以下 5 路，一次并行启动，共 8 个子代理：

| # | 方向 | 审查要点 |
|---|---|---|
| 4 | 基础安全 | 依赖安全配置、超时/重试、敏感配置项、密钥硬编码、第三方调用面 |
| 5 | 架构一致性 | 是否符合分层/既有模式；是否引入不必要抽象或破坏分层；跨文件影响与调用方 |
| 6 | 扩展性与可维护性 | 重复代码、硬编码、是否复用项目既有工具/组件、可配置性 |
| 7 | 性能与并发风险 | 循环、锁、IO 影响、并发读/写冲突、批处理与节流 |
| 8 | 影响范围分析 | 调用链影响、依赖此改动的其他模块、回滚可行性、回归风险 |

prompt 模板同档 2，替换 {方向} 为上表对应行。

## 第 5 步：报告合并与保存

- 收集所有子代理输出，按模板合并：

```markdown
## 🔍 Code Review 报告
**审查级别：** {level}
**审查范围：** {scope 描述 或 "未提交代码 (N 个文件)"}
**扫描文件：** N 个
### 📋 变更概览（文件 | 改动概述）
### 🔍 详细审查（每个子代理一节：Agent N: {方向}）
### 🎯 修复方案（优先级 P0/P1/P2 | 问题 | 文件 | 建议方案）
### ⭐ 综合评分（正确性/一致性/完整性/安全性 × 各 Agent → 综合）
综合规则：取各 agent 最低分作基准；多 agent 交叉验证一致的维度 +0.5 星；有分歧标注"⚠️ 有分歧"。
```

- **默认保存**：`.lignting/doc/review/YYYYMMDD-HHmmss-cr-report.md`
  （先确保 `.lignting/` 已被 exclude，见第 3 步；保存后告知用户路径），
  同时把报告内容输出到对话。语言默认中文（代码/标识符保留原文）。
- 更新 `.lignting/.cr-state.json`：`lastReviewAt` / `lastCommitHash` / `reviewedFiles`。

## 注意事项

1. 绝不修改任何代码。
2. 所有子代理 `run_in_background: false`，同一轮内一次并行启动（多个 subagent 调用）。
3. low 档检测到 >5 个文件 → 提示用户是否升级 middle。
4. 审查范围必须在报告开头明确标注。
5. 审查完成必须更新 `.lignting/.cr-state.json`。
