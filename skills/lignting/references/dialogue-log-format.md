# 对话记录格式

小阿卡那的宝剑/圣杯/星币三层各产出一份**对话记录**，与同层的**方案文档**并列存放。
方案文档记录"定了什么"，对话记录记录"怎么定下来的、否决了什么、还有什么没想清"。

权杖层不写对话记录，写 `round-<m>.report.md` 执行汇报。`roadmap.md` 是总览视图，同样不设
自己的对话记录——它的决策索引直接链到各层对话记录的轮次锚点（见
[roadmap-format.md](roadmap-format.md)）。

## 定位（先读这条）

| | 方案文档 | 对话记录 |
|---|---|---|
| 性质 | 拍板后的快照 | 追加式流水 |
| 读者 | 下一层的命令 | 人（未来回看时） |
| 变更 | 可重写、可被下一层推翻 | **只追加，不改写历史轮次** |
| 状态 | 不含状态 | **不含状态**（见下） |

`/ltw` 的执行汇报（`report`）与对话记录一样：**只追加、不改写历史**，也不是状态台账。

### 硬规则：不写状态

**对话记录里不出现任何"状态字段"**——不写 `status: done`、不写"待办/已完成"标记、
不维护"当前进度"。

理由：状态真相只有一处，就是 whatsnext 的 `index.md` frontmatter 和它的 `plan.md` 复选框
（见 [whatsnext-bridge.md](whatsnext-bridge.md)）。两边都记状态必然漂移。

「开放问题 / 已定决策 / 待验证猜想」是**内容分类**，用于让人快速定位聊过什么，
**不是任务状态台账**——不要给它们加状态字段，不要标"已解决/未解决"以外的元数据。

## 文件命名与位置

与同层方案文档同目录、同主名，后缀 `.dialogue.md`；`roadmap.md` 与 `report` 不属于对话记录：

```
.lignting/<feature>/
  roadmap.md                # 总览视图（不是方案文档，见 roadmap-format.md）
  direction.md              # /lts 方案文档
  direction.dialogue.md     # /lts 对话记录
  phases.md                 # /ltc 方案文档
  phases.dialogue.md        # /ltc 对话记录
  phase-<n>/
    round-<m>.md            # /ltp 方案文档
    round-<m>.dialogue.md   # /ltp 对话记录
    round-<m>.report.md     # /ltw 执行汇报（不是对话记录）
```

## 结构

```markdown
# <层名> 对话记录 · <feature> · <文档主名>

## 索引

### 开放问题
- Q1 <一句话问题>（[见 L2 · 主题](plan.dialogue.md#l2--主题)）
- Q3 <一句话问题>（[见 L4 · 主题](plan.dialogue.md#l4--主题)）

### 已定决策
- D1 <一句话结论>（[见 L3 · 主题](plan.dialogue.md#l3--主题)）
- D2 <一句话结论>（[见 L5 · 主题](plan.dialogue.md#l5--主题)）

### 待验证猜想
- H1 <一句话猜想>（[见 L4 · 主题](plan.dialogue.md#l4--主题)）

## L1 · <该轮主题>

**问**：<用户原话或要点，可精简但不要改意>

**答**：<回应要点>

<正文：展开的论证、举例、反例、代价分析>

## L2 · <该轮主题>

...
```

**层名只作标题元数据**：正文、索引与轮次标题里不写层名标签（如"宝剑层"）和相名
（如"发散相/压测相"）；轮次标题固定用 `## L<n> · <主题>`。

## 写法要求

- **轮次标题固定形状**：`## L<n> · <主题>`。
  **这是回指链接的锚点来源，形状不能改**（别写成 `## L3. 主题` 或 `## 第三轮 主题`）。
- **索引区放最前**，只列条目 + 回指，不写解释。新读者靠它跳到关心的轮次。
- **轮次编号 `L<n>` 只增不改**。追加新轮次时不动旧轮次；发现旧轮次写错了，
  在新轮次里更正并注明（"更正 L3：……"），不要回头改写历史。
- **保留用户原话的语义**。可以精简重复，但不能把用户的犹豫、疑问改写成肯定句——
  那些犹豫往往正是后面决策的依据。
- **被否决的方案要留在正文里**，附当时的否决理由。这是对话记录最值钱的部分，
  方案文档不会记它。
- **标注确定度**：`[事实·依据]` / `[推断·依据]` / `[猜想·待验证]`（规范见各命令文件）。
- **讨论重点变化的那轮要留「本轮确定的结论」小节**：写清这一轮确认了什么、还没定什么，
  下一层的回指要指得到它；用"讨论重点/节奏"描述，不写"换相"或相名。
- **不写相名/层名标签**：正文不出现相名，也不给段落贴层名标签；层名只在文档标题里作为元数据。

## 回指链接（对话里跳转的硬要求）

讨论中引用**之前任何一轮**的术语、结论、被否决方案时，**必须**带可点击的回指链接——
用户没参与过你脑子里那场讨论，不带链接就是"不知所云"（见 `lts.md` 2.3）。

**锚点生成规则**（GitHub 风格，四级标题同样适用）：

| 标题 | 锚点 |
|---|---|
| `## L3 · whatsnext 插件能不能配合` | `#l3--whatsnext-插件能不能配合` |
| `## L4 · 实现与收尾` | `#l4--实现与收尾` |
| `### 开放问题` | `#开放问题` |

规则：**全小写 → 删掉所有标点（含 `·`）→ 空格换成 `-`**（相邻空格会得到相邻的 `-`；中英文
标点都删，含 `.` `:` `,` `?` `!` `《》`；`v0.1.1` 会变成 `v011`，所以标题里能少用标点就少用）。
英文与数字原样保留；**规则边界上的标题**（带标点、带大写英文缩写）生成后自检一遍，
确保链接跳得到。

**回指写法**（相对当前文件；同在 `.lignting/<feature>/` 下只写文件名）：

```markdown
采用方案 B（[见 L4 · 实现与收尾](plan.dialogue.md#l4--实现与收尾)）。
```

| 指向 | 写法 |
|---|---|
| 同一份对话记录的其他轮次 | `[见 L3 · 主题](plan.dialogue.md#l3--主题)` |
| 同层方案文档的某节 | `[direction.md 第 2 节](direction.md#2-关键决策记录)` |
| 上一层方案文档 | `[../<上游 feature>/direction.md](../<上游 feature>/direction.md)` |

- 术语第一次出现才需要带链接，同一条回复里第二次出现可以省。
- **链接文字要能脱离链接独立看懂**：文字里带上 `L3 · 主题` 这种"文件内位置"，
  即使某个渲染器不认锚点，读者也知道去哪一节找。
- `roadmap.md` 的决策索引按同样规则链到各层对话记录的轮次锚点（见
  [roadmap-format.md](roadmap-format.md)）。

## 何时写

- **`/lts` `/ltc` `/ltp` 每轮讨论结束就追加**，不要攒到最后一次写。攒着写等于丢掉中间过程。
- **`/ltw` 不写对话记录**：执行与自测结束后写 `round-<m>.report.md`（四段式汇报），
  与对话记录一样只追加、不改写历史。
- 用户明说"别记"时跳过本轮。
- 追加前若文件不存在，按上面结构新建（先建索引区再写 `L1`）。
