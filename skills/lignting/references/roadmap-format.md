# 总计划视图格式（roadmap.md）

`.lignting/<feature>/roadmap.md` 是**人读总计划视图**：让用户在一个文件里快速看清"现在到哪、
大轮次是什么、当前轮做什么、上一轮实际发生了什么、决策在哪"。

## 定位

- **不是方案文档，不是任何命令的输入**。输入链不变：命令只读各自的源文档——`/ltc` 读
  `direction.md`，`/ltp` 读 `phases.md`，`/ltw` 读 `phase-<n>/round-<m>.md`（以及各自的
  对话记录 / report）。
- **既有 feature 的特殊命名**：本仓库 `.lignting/minor-arcana-plan/` 的方向文档实际叫 `plan.md`；
  已有 feature 按实际文件名替换模板里的 `direction.md`，新 feature 一律用 `direction.md`。
- **细节可以搬进来，但只做派生**：核心目的、要做什么、验收、改动顺序、回滚、实际结果都可写入，
  但每节必须标注「派生自 <源文档> · 同步于 <日期>；冲突以源文档为准」，roadmap 不新造结论。
- **不写完成状态**：没有复选框、百分比、"进行中/已完成/下一步待办"；状态只认 whatsnext。
  「现状」是位置指针，「回填」是已发生事实，都不是进度台账。
- **不建 `roadmap.dialogue.md`**；**不登记 whatsnext `index.md` 文件索引**（避免恢复时被当输入）；位置固定、随 git 走：`.lignting/<feature>/roadmap.md`。

## 模板

`> 层级：` 仍属于四层方案文档；roadmap 不属于四层，用下面变体（`最后同步` 每次写入都更新）。
章节顺序固定：现状/目标 → 大轮次 → 当前轮 → 执行回填 → 决策索引 → 文档地图；先回答"现在到哪"，再看前方、刚发生，最后给理由与出处。每节开头用 HTML 注释写 owner，读者不可见。

```markdown
# <feature> · 总计划

> 类型：总览视图（人读；**不是任何命令的输入**，冲突以源文档为准）
> 基准：direction.md · phases.md · phase-<n>/round-<m>.md
> 最后同步：<yyyy-mm-dd>

## 1. 一句话现状与目标
<!-- owner: /lts 首建；之后由最近一次改动"下一步"的命令覆盖本行 -->

**现状（截至 <yyyy-mm-dd>）**：大轮次见 §2；当前轮 P<n>·R<m> 见 §3；最近回填 P<n>·R<m>（<日期>）见 §4
**目标**：<一句话>（[direction.md 第 1 节](direction.md#1-目标与非目标)）
**待拍板**：见 [direction.md 第 5 节](direction.md#5-待决问题)；阶段归属见 [phases.md 第 4 节](phases.md#4-待决问题归属)

## 2. 大轮次
> 派生自 [phases.md](phases.md) · 同步于 <yyyy-mm-dd>；冲突以 phases.md 为准

<!-- owner: /ltc；行可增改；粒度到"阶段" -->

| # | 核心目的 | 要做什么 | 核心验收标准 | 链接 |
|---|---|---|---|---|
| P1 | <为什么非做这一阶段不可> | <范围> | <1–3 条> | [phases.md](phases.md) · [对话](phases.dialogue.md) |
| P2 | … | … | … | … |

**边界变更**（只追加，不改历史）
- <yyyy-mm-dd> <重划原因> → [L3 · 主题](phases.dialogue.md#l3--主题)

## 3. 当前轮
> 派生自 [计划原文](phase-<n>/round-<m>.md) · 同步于 <yyyy-mm-dd>；冲突以计划原文为准

<!-- owner: /ltp；整块替换，只保留最近一轮 -->

**Phase <n> · R<m>**（[计划](phase-<n>/round-<m>.md) · [验收标准细化](phase-<n>/round-<m>.md#5-验收标准细化)）

- 核心目的：<一句话>
- 要做什么：<…>
- 明确不做：<…>
- 验收：<1–3 条；可执行条目见计划「验收标准细化」节>
- 改动顺序：<1) → 2) → …；每步回滚点与验证命令见计划>
- 回滚：<退到哪一步、代价；不可回滚的步骤显式标出>

## 4. 执行回填
> 事实来源：各轮 report（未落盘时链 round 文档）· 同步于 <yyyy-mm-dd> · 冲突以 report 为准 · 逐轮追加

<!-- owner: /ltw；每轮一行 -->

| 轮次 | 做了什么 | 验证结果 | 与计划的偏离 | 链接 |
|---|---|---|---|---|
| P1·R1 | <改动清单摘要> | <真命令 + 真结果> | <跳过/补做/换路线；零偏离写明理由> | [report](phase-1/round-1.report.md) · [计划](phase-1/round-1.md) |

> 影响后续轮次的问题：行末追加「→ 影响后续：…」，没有就省略。

## 5. 决策索引
<!-- owner: 各层；只追加；只收影响边界/方向的决策 -->

- 方向：<一句话> —— [L4 · 实现与收尾](direction.dialogue.md#l4--实现与收尾)
- 阶段：<一句话> —— [L3 · 主题](phases.dialogue.md#l3--主题)
- 轮次：<一句话> —— [L2 · 主题](phase-1/round-1.dialogue.md#l2--主题)

## 6. 文档地图
<!-- owner: 各层；新文档落盘时追加一行 -->

| 文档 | 层 | 作用 | 链接 |
|---|---|---|---|
| direction.md | 宝剑 | 目标、非目标、关键决策 | [打开](direction.md) |
| direction.dialogue.md | 宝剑 | 方向讨论与否决记录 | [打开](direction.dialogue.md) |
| phases.md | 圣杯 | 阶段表与核心验收标准 | 待 /ltc 生成 |
| phases.dialogue.md | 圣杯 | 阶段划分讨论 | 待 /ltc 生成 |
| phase-1/round-1.md | 星币 | 改动顺序、回滚、验证 | 待 /ltp 生成 |
| phase-1/round-1.report.md | 权杖 | 四段式执行汇报 | 待 /ltw 生成 |
```

## 每节放什么 / 不放什么

| 节 | 放 | 不放 |
|---|---|---|
| §1 | 位置指针 + 日期、目标一句、待拍板链接 | 进度、完成度、百分比、下一步待办 |
| §2 | 阶段号、核心目的、要做什么、1–3 条核心验收标准、链接 | 文件/函数/步骤/回滚、状态列 |
| §3 | 最近一轮的目的、范围、明确不做、验收、改动顺序、回滚、链接 | 历史轮、完成标记、超出计划原文的细节 |
| §4 | 已发生事实、真实验证、偏离、链接 | 待办、计划、未验证判断、"已完成" |
| §5 | 按方向/阶段/轮次分组的选读条目，链对话锚点 | 全量台账、论证复述 |
| §6 | 已有文档的层、作用、链接 | `.whatsnext` 路径、绝对路径、未生成文档的死链 |

## 维护分工

| 命令 | 时机 | 只动 | 写法 | 明确不动 |
|---|---|---|---|---|
| `/lts` | 方向定型、文件不存在时新建 | 头部、§1、§5 方向组、§6 前两行 | 空节写「待 /ltc 填充」（纯文字） | §2/§3/§4 |
| `/ltc` | `phases.md` 落盘后；边界重划时 | §2、§1 现状行、§5 阶段组、§6 阶段行 | 表行增改；边界变更只追加 | §3/§4 |
| `/ltp` | `round-<m>.md` 落盘后 | §3（整块替换）、§1 现状行、§5 轮次组、§6 本轮行 | 旧轮不搬运 | §2/§4 |
| `/ltw` | 执行与自测完成后 | §4（追加一行）、§1 现状行、§6 报告行 | 回填带真命令、真结果、偏离 | §2/§3/§5 |

轮次边界：

- 新轮/单轮：`/ltp` 替换 §3、`/ltw` 追加 §4，两者都改 §1 指针；§3 不标"已完成"，旧轮不留在 §3。
- 阶段切换/重划：`/ltc` 改 §2 与 §1；重划保留旧行并标「→ 见重划行」+ 追加「边界变更」，不重写 §4。
- 方向改主意：`/lts` 只改 §1 目标句、§5、§6，提示重跑 `/ltc` 复核 §2；不直接改 §2/§3。

防覆盖：

1. 写前读最新全文，按 heading 定位，用 edit 精确替换本节，不整文件 write。
2. §4/§5/§6 与 §2「边界变更」只追加；更正用新行，不改历史行。
3. 发现别人节与源文档不一致：对话里说明 + 在该层方案文档「与上游的偏离」记录，建议跑对应命令；不静默改。
4. 同一 feature 一次只让一条命令写；并行时把 roadmap 写入指定单一 owner 或用任务依赖排序。

## 派生与同步

- **先源文档、后 roadmap**：源文档落盘并让用户过目后，再更新 roadmap 对应节；不许从 roadmap 反推方案。
- **同步日期与冲突**：每次写入更新该节「同步于」与头部「最后同步」；与源文档冲突一律以源文档为准，
  并在同一次收尾里修 roadmap，不得反过来改源文档。

## 链接策略

- 只用**相对链接**，不写绝对路径、`file://`、`.whatsnext` 路径。
- 文件级链接是硬要求；节级锚点按 [dialogue-log-format.md](dialogue-log-format.md) 的「回指链接」规则。
- 真实示例：[direction.md 第 1 节](direction.md#1-目标与非目标)、[phases.md 第 4 节](phases.md#4-待决问题归属)、
  [L3 · 主题](phases.dialogue.md#l3--主题)、[计划](phase-1/round-1.md)、
  [验收标准细化](phase-1/round-1.md#5-验收标准细化)、[report](phase-1/round-1.report.md)。
- 锚点规则：标题全小写 → 删所有标点（含 `·` `.` `：` `，`）→ 空格换 `-` → 汉字/英文/数字保留。
  因此 `## L3 · 主题` → `#l3--主题`（两个 `-`），`## 5. 验收标准细化` → `#5-验收标准细化`。标题少用
  中文标点，生成后自检；链接文字要能脱离链接看懂（带「L3 · 主题」「第 4 节」这类位置）。
- 至少要有链接的位置：头部基准、§1 目标与待拍板、§2 每行、§3 计划/验收、§4 每行、§5 每条、
  §6 每份已生成文档。

## 与现有规则的关系

- **输入链不变**：命令只读 `direction.md` / `phases.md` / `phase-<n>/round-<m>.md`；roadmap 不是第五层输入。
- **D5 不变**：`/ltp` 仍只细化即将执行的那一轮；§3 只有一轮。
- **不写状态不变**：roadmap 不出现完成状态；状态只认 whatsnext。
- **`层级` 字段不变**：四层方案文档继续用 `> 层级：`；roadmap 用「类型 / 基准 / 最后同步」。
- 本文件已加入 `verify.mjs` 的 `required` 清单；`npm run check` 会校验它存在。
