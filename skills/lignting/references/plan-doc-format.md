# 方案文档格式

小阿卡那每层产出一份**方案文档**（拍板后的快照），是**下一层命令的唯一输入**。

各层的章节清单写在各自的命令文件里（`command/lts.md`、`ltc.md`、`ltp.md`、`ltw.md`），
本文件只定义四层共用的写法约定。

## 每份方案文档都要有的头部

```markdown
# <文档标题>

> 层级：<宝剑 / 圣杯 / 星币 / 权杖>
> 上游：<上游方案文档绝对路径，或"无（本层为起点）">
> 对话记录：<同层对话记录的相对路径>
> 生成日期：<yyyy-MM-dd>
```

**上游路径必须有**。下一层靠它做偏离比对；跨对话恢复时也靠它串起完整链条。

## 回指写法

方案文档里每条**关键结论**要回指对话记录，让读者能追到当时的语境，而不是只看到一个
孤零零的结论：

```markdown
- 采用方案 B：渲染层做抽象，先抽后搬。
  （见 [direction.dialogue.md](direction.dialogue.md) L4）
```

回指粒度：**决策级**条目必带，纯事实陈述（现状清单之类）可省。

## 偏离记录写法

下游层可以推翻上游结论——它离实现更近、信息更多。但**偏离必须显式可见**，
不许默默绕开。

每份方案文档末尾必须有「与上游的偏离」一节（无偏离也要写一行）：

```markdown
## 与上游的偏离

| # | 上游结论 | 本层结论 | 理由 | 建议 |
|---|---|---|---|---|
| 1 | 阶段 2 先做接口抽象 | 改为先做数据迁移 | 抽象依赖的存量数据尚未摸清 | 建议同步修订 phases.md 第 2 节 |
| 2 | — | — | 无偏离 | — |
```

- **理由必填**，写清是什么新信息导致的偏离。
- **建议必填**：写"建议同步修订 <上游文档> <章节>"，或"建议维持上游不变，本层特例"。
- 偏离项若影响后续轮次，还要在交付时**主动提示用户**（见各命令的收尾节）。

## 通用写法要求

- **自包含**：读者是"没参与过这次对话的人"。不依赖对话上下文，不写"我们上次说的那个方案"。
- **不含状态**：不写"当前进度""已完成/未完成"。状态只认 whatsnext（见
  [whatsnext-bridge.md](whatsnext-bridge.md)）。
- **标注确定度**：`[事实·依据]` / `[推断·依据]` / `[猜想·待验证]`。
  事实给依据（文件/符号/命令输出），猜想给验证路径。
- **代价必须写出来**：每个方案后面附代价。没有代价的方案通常是没想清楚。
  注意区分——**代价是必然付的，风险是可能付的**，两者分列。
- **不写具体文件路径和函数名**（除非用户明确要求，或该细节本身是不可逆的架构契约）。
  往下走的层级才该谈"改哪个文件"。

## 落盘

- 目录 `.lignting/<feature>/`，**随 git 走**（架构决策要能被 review）。
- 默认建议路径，用户可改；落盘后把路径告诉用户，并推荐下一步命令。
- 落盘前先输出到对话让用户过目——**除非**该层流程明确要求直接落盘。
